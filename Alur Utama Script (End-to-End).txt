**Alur Utama Script (End-to-End)**

1. **Awal loading aplikasi**
- Entry point ada di [main.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/main.dart).
- `main()` melakukan:
  1. `WidgetsFlutterBinding.ensureInitialized()`
  2. inisialisasi Firebase (`Firebase.initializeApp(...)`)
  3. membuat `MasterFirestoreRepository` jika Firebase aktif
  4. `runApp(SchoolFinanceApp(...))`

2. **Root app dan routing UI**
- Root UI ada di [school_finance_app.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/app/school_finance_app.dart).
- `SchoolFinanceApp` adalah stateful app utama:
  - menyiapkan tab bawah: Dashboard, Transaksi, Laporan, Pengaturan
  - menyiapkan FAB tengah (quick menu Transaksi/Absensi)
  - menyiapkan state transaksi, absensi, filter, dan koneksi ke controller master data.

3. **Master data dan sinkron**
- Logic master data ada di [master_data_controller.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/features/master_data/application/master_data_controller.dart).
- `MasterDataController.initialize()` dipanggil saat app start untuk fetch:
  - kategori
  - user
  - role
  - group/subgroup/murid
- Jika Firebase error (mis. Firestore API disabled), controller fallback ke data lokal dan set pesan error.

4. **Akses Firestore (repository layer)**
- Semua operasi Firestore ada di [master_firestore_repository.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/features/master_data/data/master_firestore_repository.dart).
- Koleksi yang dipakai:
  - `master_categories`
  - `master_users`
  - `master_user_roles`
  - `master_student_groups`
  - `master_student_sub_groups`
  - `master_students`
- Controller memanggil repository untuk `fetch/upsert/delete`.

5. **Flow transaksi**
- Model transaksi ada di [tx_item.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/features/finance/domain/models/tx_item.dart).
- Di UI transaksi:
  - tambah/edit lewat `showTxForm(...)` di [school_finance_app.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/app/school_finance_app.dart)
  - validasi duplikat, validasi nominal, dan mode checklist murid
  - `setState` menyimpan transaksi ke list lokal `txs`
- Untuk kategori checklist:
  - bisa `nominal per item x jumlah ceklis`
  - atau mode menabung `nominal per murid` (disimpan di `checkedStudentAmounts`)

6. **Flow absensi**
- Model absensi ada di [attendance_session_item.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/features/attendance/domain/models/attendance_session_item.dart).
- Form absensi di `showAttendanceSessionForm(...)`:
  - pilih group/subgroup
  - isi status tiap murid (hadir/sakit/izin/alpa)
  - ada `Apply All` untuk isi massal
- Data sesi disimpan ke list lokal `attendanceSessions`.

7. **File pengaturan (Settings)**
- UI pengaturan ada di komponen `SettingsPage` dalam [school_finance_app.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/app/school_finance_app.dart).
- Fungsinya:
  - dark mode
  - status Firebase
  - CRUD user
  - CRUD role
  - CRUD kategori (termasuk flag useGroup/useSubGroup/useStudent)
  - CRUD group/subgroup/murid
  - backup/restore JSON

8. **Simpan data dan backup/restore**
- Simpan transaksi/absensi saat ini masih in-memory (`setState` list lokal).
- Backup/restore ada di fungsi `backup()` dan `restore()` di [school_finance_app.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/app/school_finance_app.dart):
  - Backup: serialisasi ke JSON + copy ke clipboard
  - Restore: parse JSON, replace list lokal, dan sinkron master via controller

9. **Export laporan**
- Export ada di [school_finance_app.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/app/school_finance_app.dart):
  - `exportCsv(...)` untuk CSV (copy ke clipboard)
  - `exportPdf(...)` pakai package `pdf` + `printing`
- Laporan UI (`ReportsPage`) memanggil fungsi ini untuk data bulanan/tahunan.

10. **Theme dan tampilan**
- Theme global ada di [app_theme.dart](/d:/Project/PROJECT%20X/sekolah-mobile-app/catat_kelas/lib/core/theme/app_theme.dart).
- Dipakai di `MaterialApp` untuk light/dark dan konsistensi visual.

File utama yang mengandung UI + logika auth: school_finance_app.dart
Widget login: _AuthLoginPage (stateful) — di sinilah field email/password & tombol login/lupa-password berada
Fungsi validasi: _isValidEmail, _isStrongPassword
Fungsi login: _login() → memanggil FirebaseAuth.instance.signInWithEmailAndPassword(...)
Toggle visibility password: state boolean _obscure + suffixIcon pada TextFormField
Forgot password: _forgotPassword() → FirebaseAuth.instance.sendPasswordResetEmail(...) (saya sudah memperbarui supaya memunculkan dialog ketika field kosong)
Google Sign-In (opsional): _signInWithGoogle() → GoogleSignIn() + FirebaseAuth.instance.signInWithCredential(...)
App routing setelah login: SchoolFinanceApp.build() menggunakan StreamBuilder pada FirebaseAuth.instance.authStateChanges() — bila user non-null → tampilkan main app; bila null → tampilkan _AuthLoginPage
Detail lengkap — file dan alur langkah demi langkah

Di mana UI password berada
File: school_finance_app.dart
Widget: class _AuthLoginPage extends StatefulWidget dan state _AuthLoginPageState.
Komponen UI relevan:
Email field:
TextFormField(controller: _emailCtrl, keyboardType: TextInputType.emailAddress, ...)
Password field:
TextFormField(controller: _passwordCtrl, obscureText: _obscure, decoration: ..., suffixIcon: IconButton(...))
Variabel state controlling visibility: bool _obscure = true;
Saat pengguna mengetuk suffixIcon, handler memanggil setState(() => _obscure = !_obscure), sehingga obscureText berubah dan teks password muncul/tersembunyi.
Tombol Login:
FilledButton(onPressed: _loading ? null : _login, ...)
Link “Lupa Password?”:
TextButton(onPressed: _forgotPassword, child: const Text('Lupa Password?'))
Tombol Daftar:
TextButton(... Navigator.push to _AuthRegisterPage ...)
Validasi input password / email yang dipakai sebelum submit
Fungsi helper:
_isValidEmail(String) — regex sederhana memeriksa format email.
_isStrongPassword(String) — regex memeriksa minimal 8 karakter dan kombinasi huruf+angka.
Validator pada TextFormField password:
Jika kosong → 'Password wajib diisi'
Jika tidak memenuhi _isStrongPassword(...) → 'Minimal 8 karakter, kombinasi huruf dan angka'
Form dibungkus Form(key: _formKey) sehingga _login() memanggil if (_formKey.currentState?.validate() != true) return; sebelum melakukan autentikasi.
Fungsi yang melakukan login (logika)
Nama fungsi: _login() di _AuthLoginPageState.
Alur dalam _login():
Validasi form (lihat poin 2).
setState → _loading = true (men-disable tombol).
Panggilan Firebase Auth: await FirebaseAuth.instance.signInWithEmailAndPassword( email: _emailCtrl.text.trim(), password: _passwordCtrl.text, );
Jika ada FirebaseAuthException → tampilkan pesan error ke user:
Di-handle dengan menampilkan SnackBar(content: Text(_firebaseAuthErrorMessage(e)))
_firebaseAuthErrorMessage(FirebaseAuthException e) adalah fungsi map error.code → pesan user-friendly (mis. 'user-not-found', 'wrong-password', dll).
Di finally: jika mounted → setState _loading = false.
Efek samping penting:
Jika sign-in berhasil, Firebase mengubah state auth; StreamBuilder di SchoolFinanceApp (lihat bagian 4) akan menerima event user non-null dan otomatis menampilkan halaman utama aplikasi (tanpa perlu Navigator.push manual).
Bagaimana app memilih untuk menampilkan login vs main app
File: school_finance_app.dart, method build() di SchoolFinanceApp:
Jika widget.firebaseEnabled == true → app menggunakan: StreamBuilder<User?>( stream: FirebaseAuth.instance.authStateChanges(), builder: (ctx, snap) { if (snap.connectionState == ConnectionState.waiting) return _AuthLoadingPage(); final user = snap.data; return user == null ? const _AuthLoginPage() : _buildMainScaffold(); } )
Jika firebaseEnabled == false → langsung tampil home tanpa login (app bypass auth).
Jadi login sukses tidak meng-navigate secara eksplisit; perubahan auth state yang dipublikasikan Firebase menyebabkan widget rebuild dan menampilkan main app.
Forgot Password (alur reset password)
Fungsi: _forgotPassword() di _AuthLoginPageState.
Alur:
Ambil email dari _emailCtrl.text.trim().
Jika email invalid/empty → sebelumnya menampilkan SnackBar; sekarang kode telah dimodifikasi untuk memunculkan dialog input email bila field kosong (saya yang mengubah).
Memanggil: await FirebaseAuth.instance.sendPasswordResetEmail(email: email);
Jika sukses → tampilkan SnackBar: 'Link reset password telah dikirim ke email.'
Jika error FirebaseAuthException → tangani dan tampilkan pesan user-friendly via _firebaseAuthErrorMessage.
Catatan: reset password mengirim email dari Firebase; agar email dikirim, Authentication provider Email/Password harus aktif di Firebase Console.
Google Sign-In (opsional)
Fungsi: saya menambahkan _signInWithGoogle() yang:
memanggil GoogleSignIn().signIn() → mengambil googleAuth → buat credential GoogleAuthProvider.credential(...) → FirebaseAuth.instance.signInWithCredential(credential)
Jika berhasil → auth state berubah → app masuk otomatis.
Perlu konfigurasi Firebase (SHA cert di Android, konfigurasi iOS/Web) agar sign-in bekerja.
Register flow
Widget: _AuthRegisterPage (stateful) dan _register() method:
_register() mem-validasi form lalu memanggil: await FirebaseAuth.instance.createUserWithEmailAndPassword( email: _emailCtrl.text.trim(), password: _passwordCtrl.text, );
Jika berhasil → Navigator.pop(context) ke layar login (user bisa login).
Jika error → tampilkan SnackBar (menggunakan _firebaseAuthErrorMessage).
Error handling & user feedback
Semua error Firebase diubah ke pesan via _firebaseAuthErrorMessage(FirebaseAuthException e) yang menangani banyak kode error dan memberikan pesan lokal (Bahasa Indonesia).
UI feedback: SnackBar dipakai untuk menampilkan pesan sukses/gagal.
Tombol LOGIN menggunakan _loading untuk men-disable saat operasi berlangsung.

Jalankan app dengan Firebase enabled (di main() app mencoba Firebase init; jika init gagal, firebaseEnabled akan false dan app melewati login screen).
Jika firebaseEnabled == false maka tombol Lupa Password tidak relevan karena login screen tidak muncul.
Pastikan user/email ada di Firebase Console → Authentication → Users.
Pastikan Email/Password provider diaktifkan di Firebase Console → Authentication → Sign-in method.
Uji alur:
Buka app, masukkan email yang terdaftar, tekan "Lupa Password?"
Jika email field kosong → sekarang akan muncul dialog input email (karena perubahan saya). Isikan email dan klik Kirim.
Periksa output/log konsol saat panggilan sendPasswordResetEmail(...) — apakah ada exception? (catat pesan).
Periksa inbox/spam email.
Jika tidak terkirim:
Periksa Firebase Console → Authentication → Templates → Reset Password (pastikan template tidak dimodifikasi jadi gagal).
Jika Anda menggunakan custom SMTP (di Console) pastikan kredensial SMTP valid.
Cek logs di console (jika ada) atau tangkap FirebaseAuthException message.
